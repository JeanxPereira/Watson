# Trace Probes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** While a GIF trace runs, record the EE registers and chosen memory ranges every time execution reaches chosen program counters, in the same file and in order with the packets, so that arithmetic read from disassembly can be recomputed from its real inputs and compared with what was actually sent to the GS.

**Architecture:** One more hook, in the EE interpreter's instruction loop, calls into `GifTrace` when probes are set. A probe is a program counter and a list of memory ranges given relative to a register, absolute, or through a pointer. The server passes probes with `gif_trace_start`, reads `probe` records back with the rest of the trace, and tells each probe which packet it precedes.

**Tech Stack:** C++ (PCSX2 v2.9.94 core), Python (`MakeHooks.py`), TypeScript on Node 25, `node:test`.

**Spec:** `docs/superpowers/specs/2026-10-01-watson-design.md` section 5.5 (the trace). Probes are an addition to it; the section is amended in Task 3.

## Probe grammar (wire and tool)

```
probes  = point { ";" point }
point   = pc [ "=" range { "," range } ]
range   = [ "*" ] base [ "+" hex ] ":" hex          length in bytes
base    = register name | "0x" hex                   zero at v0 v1 a0-a3 t0-t7 s0-s7 t8 t9 k0 k1 gp sp s8 ra
```

`a0+0x10:0x40` reads 0x40 bytes at `a0 + 0x10`. `*a1+0x60:0x40` reads the 32-bit pointer at `a1 + 0x60` and then 0x40 bytes where it points. Limits: 32 points, 8 ranges per point, 0x4000 bytes per range. A probe fires before the instruction at its `pc` executes.

## Record

```json
{"type":"probe","pc":"0x00232da0","frame":2490,"gpr":"<32 registers, 8 hex digits each, low 32 bits>","fpr":"<32 registers, 8 hex digits each, raw bits>","mem":[{"address":2345678,"hex":"…"},{"address":0,"error":"not readable"}]}
```

Memory is read from EE RAM (`0x00000000..0x01FFFFFF` after masking the segment bits `0xE0000000` for kseg addresses) and the scratchpad (`0x70000000..0x70003FFF`); anything else, or a range that runs past the end, is `error`.

## Review Focus

1. A malformed probe string: refused whole, naming the offending part; no trace file is left open.
2. A probe whose pointer or range is not in guest memory: recorded with `error`, the trace goes on.
3. Probes given without the interpreters: refused with the trace, as before.
4. A probe program counter that never executes: zero records, and the summary says so per point.
5. The hook's cost with no probes set: one flag test per instruction; the live determinism and parity gates still pass.

### Task 2: Server passes probes and reads them back

**Files:** Modify `Server/src/debug-server-client.ts`, `Server/src/navigation.ts`, `Server/src/gs/trace.ts`, `Server/src/index.ts`; tests in `Server/tests/client.test.mjs`, `navigation.test.mjs`, `gs-trace.test.mjs`, `live.test.mjs`.

**Interfaces — produces:**

```ts
// debug-server-client.ts
export interface ProbeSpec { pc: string; ranges?: string[] }
export function probeString(probes: ProbeSpec[]): string;          // "0x232da0=a0:0x160,a1:0xc0;0x232aa4"
gifTraceStart(path: string, probes?: ProbeSpec[]): Promise<void>;
// navigation.ts
takeGifTrace(emulator, path, frames, probes?: ProbeSpec[])
// gs/trace.ts
export interface Probe { pc: number; frame: number; gpr: number[]; fpr: number[]; mem: { address: number; bytes: Buffer | null }[]; preroll: boolean; at: number }
Trace.probes: Probe[]        // `at`: how many of `packets` (or of `preroll`) came before it
```

Tests to write first, each seen failing:

- `probeString` joins points with `;`, ranges with `,`, and a point with no ranges is just its pc; a pc that is not hex, or a range holding `;`, `,` or `=`, throws naming it.
- `gifTraceStart` sends `probes` only when given (fake server).
- `takeGifTrace` hands its probes to `gifTraceStart`.
- `readTrace` returns probes with 32 `gpr` and 32 `fpr` numbers, memory as bytes or `null` for an `error`, `preroll` and `at` set from their place among packets; a probe record with a `gpr` of the wrong length makes the trace incomplete, naming the line.
- `formatTrace` lists each probed pc with its count.
- live (interpreters only): probes at the two instructions that start the channels (found in the trace itself: the `pc` of its `vif1` and `gif` origins) fire exactly as many times as there are origins of each channel in a second trace of the same frames from the same state; a bad probe string is refused and a following plain trace starts; a probe range through a null pointer is recorded with `bytes` null.
