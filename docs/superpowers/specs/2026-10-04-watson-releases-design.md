# Watson releases that follow PCSX2

Watson is PCSX2 plus a few files and a small patch. This note describes how GitHub Actions rebuild
it on each new PCSX2 version and publish the result.

## Trigger

`.github/workflows/track-pcsx2.yml` runs every day at 06:17 UTC and on `workflow_dispatch`.

- No ref given: the newest PCSX2 release of the channel. `nightly` (the default) is the newest
  release including pre-releases (`repos/PCSX2/pcsx2/releases?per_page=1`); `stable` is
  `releases/latest`. Watson pins a nightly (v2.9.94), and the last stable (v2.8.2) is older than
  that pin, so stable is opt-in.
- `pcsx2_ref` given: any tag, branch or commit. A tag names the release by itself; anything else
  is named `g<first 9 hex digits of the commit>`.
- The run stops at once when the release for that version already exists.

`.github/workflows/ci.yml` runs on every push to main and on pull requests: the server's offline
tests, a check that the hooks apply on the pinned commit, and a Windows build on the pinned
commit. It publishes nothing.

## Applying the hooks to another PCSX2

`Emulator/hooks.patch` holds only call sites: an include, then one call into Watson's own files
(`DebugServer`, `GifTrace`, `SpuTrace`) per hook. Logic stays in those files. 55 lines are added
and one is changed, in 17 files and 40 hunks. The patch is generated by `Emulator/MakeHooks.py`
with `git diff --full-index`, so it records the full ids of the pinned blobs.

`Emulator/ApplyHooks.py <pcsx2 tree>` copies Watson's sources into `pcsx2/DebugTools`, then:

1. applies the patch directly when it applies;
2. otherwise fetches the pinned commit (depth 1) for its blobs and runs `git apply --3way`, which
   merges each hooked file against its pinned version, so moved code does not matter;
3. otherwise puts the hooked files back, applies each hunk alone (three-way), and reports every
   failing hunk with the conflict git left. It exits 1.

`--report <file>` writes the same report as Markdown. Result on 2026-10-04: v2.9.94 (pinned and
newest nightly) applies cleanly; v2.9.60 cleanly; v2.9.30 and v2.8.2 by a three-way merge of
`Counters.cpp`; v2.4.0 and v2.0.0 fail on one hunk in `SPU2/Mixer.cpp`, the only hunk that changes an
upstream line.

## On conflict

The `hooks` job opens one issue titled `Hooks do not apply on PCSX2 <version>` with the report in
its body, or rewrites the body of the open issue with that title, and the run stops. A build or
test failure opens or updates `Watson does not build on PCSX2 <version>` the same way. Nothing is
published. A fix is a change on main: thin the hook, or move the anchor in `MakeHooks.py` and
regenerate the patch. The next scheduled run tries again.

## Build and artifacts

`.github/workflows/build-windows.yml` (reusable) follows PCSX2's Windows CI: runner
`windows-2025-vs2026`, CMake with Ninja under vcvars, `-DQT_BUILD=ON -DDISABLE_ADVANCE_SIMD=ON`,
plus `-DENABLE_GSRUNNER=ON`, then `cmake --install`, which copies the Qt runtime and the other
dependencies into `bin/`. The `deps` directory is cached under PCSX2's own key (the hash of
`build-dependencies.bat` and its patches), plus the source of the dependencies:

- `prebuilt` (default): PCSX2's published `pcsx2-windows-dependencies.7z`, the same archive
  `Build.ps1` uses. The asset's upload time is part of the cache key.
- `source`: PCSX2's `build-dependencies.bat` from the tree being built, for a version whose
  dependencies differ from the published archive.

The release archive `Watson-<version>-pcsx2-<pcsx2 version>-windows-x64.zip` holds `PCSX2/` (the
installed `bin/`, without debug symbols), `Server/` (`dist/` with its runtime `node_modules`),
`Emulator/Run.ps1`, `watson-applied.patch`, `LICENSE` and `README.txt`. With `WATSON_PCSX2_EXE`
set to `PCSX2\pcsx2-qt.exe`, the server launches that build; `Run.ps1` uses the Qt runtime beside
the executable when it is there. Linux is not built: Watson's launcher is Windows-only. macOS is out
of scope.

## Versioning

The release tag is `watson-<watson version>-pcsx2-<pcsx2 version>`, where the Watson version is
`Server/package.json` `version`, for example `watson-0.1.0-pcsx2-v2.9.94`. A release on a PCSX2
pre-release is itself a pre-release. Releases are never replaced: a new Watson release on the same
PCSX2 version needs a version bump. `Emulator/upstream.json` stays the local development pin and is
not changed by the workflows.

## GPL-3.0

PCSX2 and Watson are GPL-3.0. Each release names the exact source in its notes: the Watson commit
the workflow ran on and the PCSX2 tag with its commit. It attaches `watson-applied.patch`, the full
diff of the built tree against that PCSX2 commit (Watson's sources and the hooks, as merged), which
is also inside the archive with `LICENSE`. The workflows use only `GITHUB_TOKEN`, with `contents:
read` by default, `issues: write` for the jobs that report, and `contents: write` for the job that
publishes.
